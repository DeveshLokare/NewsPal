# Deploying NewsPal

How the pieces fit once deployed:

```
Phone (NewsPal app) ──HTTPS──▶ Render: newspal-api (Docker, free, Singapore)
                                   │            └──▶ Free News API (news, ≤ 4,600 calls/day)
                                   └──▶ Neon: Postgres 16 (free, Singapore)
```

Everything in this repo is ready: `backend/Dockerfile`, `render.yaml` (Render Blueprint) and the production settings in `backend/src/main/resources/application.yml`. The steps below are the parts that need your accounts. Plan on about 30 minutes, most of it waiting for the first build.

---

## 1. Put the code on GitHub

Render deploys from a Git host.

The repository is https://github.com/DeveshLokare/NewsPal and is already set as `origin`. Push from a terminal in the `NewsPal` folder:

```bash
git push -u origin main
```

Git opens a GitHub sign-in the first time (Git Credential Manager). If it says "Invalid username or token", sign in again when prompted; GitHub no longer accepts account passwords for git, only the browser sign-in or a personal access token.

> No secrets are committed. The JWT secret, database password and Free News API key only ever go into Render's dashboard.

## 2. Create the database on Neon

1. Sign up at https://neon.tech (free plan).
2. **Create project**:
   - Name: `newspal`
   - Postgres version: **16**
   - Region: **AWS Asia Pacific (Singapore)**, the same region as the Render service
3. In the project's **Connect** dialog:
   - Database: create one named `newspal` (or keep the default `neondb` and use that name below)
   - Turn **Connection pooling off** (use the *direct* connection). The backend pools its own connections, and Flyway migrations need a direct connection.
4. From the connection string `postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require…`, note these three values:

| Render variable | Value |
|---|---|
| `SPRING_DATASOURCE_URL` | `jdbc:postgresql://HOST/DBNAME?sslmode=require` |
| `SPRING_DATASOURCE_USERNAME` | `USER` |
| `SPRING_DATASOURCE_PASSWORD` | `PASSWORD` |

`HOST` looks like `ep-something-123456.ap-southeast-1.aws.neon.tech`. The JDBC URL has **no** user or password in it; those go in their own variables.

You don't need to create any tables. The backend creates them (Flyway) on its first start.

## 3. Create the backend on Render

1. Sign up at https://render.com with your GitHub account.
2. **New → Blueprint**, then pick the `newspal` repository. Render reads `render.yaml` and shows a service called `newspal-api`.
3. Fill in the values it asks for:
   - `SPRING_DATASOURCE_URL`, `SPRING_DATASOURCE_USERNAME`, `SPRING_DATASOURCE_PASSWORD`: from step 2
   - `FREENEWS_API_KEY`: your key from https://www.freenewsapi.io. Leave it empty to run without fetching news.
   - `JWT_SECRET` is generated by Render automatically.
4. **Apply**. The first build takes about 5–10 minutes.
5. When the dashboard says **Live**, open (using your service's URL, shown at the top of its page):
   - `https://newspal-api.onrender.com/actuator/health` → `{"status":"UP"}`
   - `https://newspal-api.onrender.com/api/categories` → the 8 categories. This means the database is connected and migrations ran.

Later pushes to `main` that change anything under `backend/` redeploy automatically.

## 4. Check the free-tier behaviour

- **Render** puts the service to sleep after 15 minutes without requests. The next request wakes it in about a minute; the app shows "Waking up the server…" meanwhile.
- **Neon** suspends the database after 5 minutes without queries. In the Neon dashboard, the compute should show **Idle** a few minutes after a job run or after you stop using the app. The jobs workflow (§6) wakes it every 2 hours for a few minutes, which costs about 15 of the 100 free compute-hours a month. If it never goes idle, check that nothing else is pinging the API.
- **Free News API:** 5,000 requests a day. Refreshes are capped at 3,600 calls a day, plus 1,000 for older news, and fetching pauses until the daily reset if fewer than 100 are left. The logs show `Free News API listed … articles` for each list call.

## 5. Run the app on your Android phone

This needs the Android SDK, which isn't installed on this PC yet.

1. Install **Android Studio** from https://developer.android.com/studio (default options), open it once, and let it install the SDK.
2. Accept the Android licenses:

```bash
C:\src\flutter\bin\flutter.bat doctor --android-licenses
```

3. Build the app against your Render backend (use your real service URL):

```bash
C:\src\flutter\bin\flutter.bat build apk --release --dart-define=API_BASE_URL=https://newspal-api.onrender.com
```

   The APK is at `mobile/build/app/outputs/flutter-apk/app-release.apk`.
4. To install it, either:
   - **USB:** enable *Developer options → USB debugging* on the phone, connect it, then run `C:\src\flutter\bin\flutter.bat install` from the `mobile` folder.
   - **No cable:** copy the APK to the phone and open it (allow "install unknown apps" for your file manager).

The release build is signed with Flutter's debug key, which is fine for your own phone. Publishing to the Play Store would need a real signing key; that's not covered here.

## 6. Schedule the background jobs (GitHub Actions)

Render's free plan sleeps, so a GitHub Actions workflow (`.github/workflows/jobs.yml`) wakes the API every 2 hours. Each run refreshes every news category and, once a day, deletes articles older than 7 days. It needs one shared secret, `JOB_TOKEN`, set in two places.

1. Make a random token (48 hex characters). In PowerShell:

   ```powershell
   $b = New-Object byte[] 24; [Security.Cryptography.RandomNumberGenerator]::Create().GetBytes($b); ($b | ForEach-Object { $_.ToString('x2') }) -join ''
   ```

2. **Render:** on the `newspal-api` service, open **Environment**, add `JOB_TOKEN` with that value, then **Save changes**. Render redeploys.
3. **GitHub:** in the repository, open **Settings → Secrets and variables → Actions**:
   - **Secrets** tab → **New repository secret**: name `JOB_TOKEN`, the same value.
   - **Variables** tab → **New repository variable**: name `API_BASE_URL`, value your service URL, e.g. `https://newspal-api.onrender.com`.
4. **Actions** tab → **Background jobs** → **Run workflow**. The run should end green with `HTTP 202: {"started":true}` in its log, and Render's logs should show `Refreshed …` lines followed by `Job pass finished`.

After that it runs on its own every 2 hours (GitHub can start scheduled runs a few minutes late). A red run with `404` means the two `JOB_TOKEN` values don't match. GitHub pauses schedules on repositories with no commits for 60 days; if that happens, re-enable the workflow from the Actions tab.

Free-tier cost: Render is awake about 3 hours a day for these runs, well within its 750 free hours a month, and they use at most 3,600 of Free News API's 5,000 daily requests.

## Troubleshooting

| Symptom | Likely cause |
|---|---|
| Render build fails at `mvnw` | Check the build log; a network blip while downloading dependencies usually passes on **Manual Deploy → Clear build cache & deploy**. |
| Health check fails, logs show `Connection refused` or `password authentication failed` | Wrong `SPRING_DATASOURCE_*` values. Check the URL starts with `jdbc:postgresql://` and has no `user:password@`. |
| `FATAL: invalid value for parameter "TimeZone"` | The JVM isn't in UTC. The Dockerfile sets `-Duser.timezone=UTC`; make sure Render builds from `backend/Dockerfile`. |
| App says "Can't reach NewsPal right now" | Wrong `API_BASE_URL` in the build, or the service is still waking up. Open `/actuator/health` in a browser. |
| News stops updating while nobody uses the app | The jobs workflow isn't running or failing: check the **Actions** tab (§6). |
| Feed stays empty | `FREENEWS_API_KEY` is empty or rejected, or the daily budget is used up. The logs show `News provider disabled` or `quota used up`. |

## Optional: backups

Neon keeps a short restore window on the free plan. For an extra copy of what can't be re-fetched (users and archives):

```bash
pg_dump --no-owner -Fc -t users -t user_categories -t archived_articles "postgresql://USER:PASSWORD@HOST/DBNAME?sslmode=require" > newspal-backup.dump
```
